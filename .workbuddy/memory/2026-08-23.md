## AccordionTrigger 折叠图标修复（用户反馈：图标没显示）
- 根因（看 dist-lib/shadcn-vue.es.js line 24291-24298 实际模板）：shadcn-vue-cdn 的 AccordionTrigger 用 `group/accordion-trigger` 命名 group（**不是** `group`），默认在 `icon` slot fallback 渲染两个 ChevronDown 跟随 `aria-expanded` 切换 hidden/inline。我之前：
  1. 用 `template #icon` 覆盖默认 chevron 但没参与样式约定（图标没有 `data-slot=accordion-trigger-icon`、没跟随命名 group 旋转）
  2. 旋转动画类名写错：`group-data-[state=open]:rotate-90`（基于 `data-state`，正确 group 命名空间是 `accordion-trigger` + 用 `aria-expanded` 而非 `data-state`）
- 修复：折叠图标放在 default slot 标题前（左侧），用 trigger 的命名 group 选择器 `group-aria-expanded/accordion-trigger:rotate-90`（展开时旋转 90°），同时 `<template #icon />` 清空默认 chevron 避免右侧 ml-auto 重复图标。
- vue-tsc 通过。
- **教训**：用 shadcn-vue-cdn 包装组件前，先看 `node_modules/<pkg>/dist-lib/shadcn-vue.es.js` 实际 render 函数确认 class/group/slot 默认行为，不要凭文档猜。"accordion-trigger" 是命名 group 关键字 + `aria-expanded` 是状态键（不是 `data-state`）。

## AccordionTrigger 折叠图标位置二次修复（用户反馈：图标应在标题前，不是后面）
- 用户看到 trigger 标题**右侧**有图标（应该是左侧），反馈"你的图标应该在前面，而不是在后面"。
- 二次根因：
  1. 直接在 default slot 放 svg + 标题 + `<template #icon />`，trigger 的 `flex justify-between` 把多根节点散开分布（svg 没和标题贴在一起）。
  2. `<template #icon />`（自闭合空 template）被 Vue 编译器视为「没提供 icon slot」，shadcn-vue-cdn 的 AccordionTrigger 内部 `R(e.$slots, "icon", {}, fallback)` 检测到没 slot，走 fallback 渲染默认 ChevronDown（line 24292-24298 验证：两个 chevron div 跟随 aria-expanded 切换 hidden/inline），所以右侧那个图标是**默认 chevron**，不是我的图标。
- 修复：
  - default slot 包一个 `<span class="inline-flex items-center">`，把 svg + 标题整体作为单一根节点，确保 trigger flex 里它是靠左的 item。
  - icon slot 主动提供 `<span class="hidden" />` 占位（不是空 template）—— 关键：让 render 函数检测到 slot 有内容（哪怕 display:none），不再走 fallback 默认 chevron。
  - 旋转动画 `group-aria-expanded/accordion-trigger:rotate-90` 保留。
- vue-tsc 通过。
- **教训**：①shadcn-vue-cdn 的 `icon` slot 是用「slot 提供实际内容（哪怕 hidden）」vs「没提供 slot」区分，不是「空 slot」——空 template 仍走 fallback。②trigger 的 flex `justify-between` 会把多根 default slot 子元素散开，包成单一根元素才能保证位置可控。③user 自己动手改 AxJsonViewer 时连带触发 RequestLogDetailView.vue 里 `RiArrowRightSLine` 未使用 import 导致 tsc 报错——记忆日志条目里残留「顺手移除」其实是误判，import 是必要的（这次二次修复用上了）。
