## 转发日志架构调查（codegraph）→ 写档 ROUTE-LOG-ARCHITECTURE.md

用户要求先复述其"组级状态机"自愈构想（看组内最后一条成功与否 + 有无后续 running），用 codegraph 调查后写完整架构文档到 `docs/ROUTE-LOG-ARCHITECTURE.md`。

**核心结论**：
1. **贯通三类请求（普通/虚拟/视觉）的参数是 `request_id`（X-Request-Id）**，不是 virtual_model。同一请求的视觉 attempt + 主链路切换 attempt 全挂同一 request_id 下，step_no 共享单调递增空间（视觉在前，`__route_step` 记录视觉最后 step，主链路从 step+1 续接，`__main_route_step` 独立计数防误判 action）。
2. **三条链路**：普通/虚拟模型共用 `HandleProxy → proxyForward` 底层；**视觉不走 proxyForward**，走独立 `callVision`（vision/service.go:517 自己 new http.Client 直连 `ch.BaseURL + /chat/completions`），通过 `visionAttempt → routeLog.Attempt` 写同 request_id 日志。
3. **虚拟模型聚合标记**：aggregate 插件 `HandleProxyBeforeUpstream` 设 `Metadata["__virtual_model"]`（如 auto）→ model-gateway 二次 Start（UPSERT）补 virtual_model 列；失败切换走 `tryProxyAggregateFailover`，attempt action="切换模型"。
4. **状态器实现位置结论**：真正三类都经过的共同点是 route-log 的 Start/Attempt/Finish（vision 也调 routeLog.Attempt），状态器挂这里最稳；且"是否继续"判断应以 DB 为准（查该组是否有更新且仍 running 的记录），不依赖进程内存（重启即失）。
5. 表结构：`route_requests`（request_id PK + requested_model + virtual_model + result...）、`route_attempts`（id + request_id FK + step_no UNIQUE(request_id,step_no) + action + model + channel_id + metadata_json...），core/db/migrate.go:80-116。
6. 前端 3s 刷新链：refresh(list) → refreshActiveDetails（已展开，running 必刷/终态重试5次）→ selfHealStuckLogs（running>60s 调 detail 触发后端自愈）。
7. 用户新方案待确认点：分组键选 request_id / virtual_model / requested_model 哪个；状态器放 route-log 服务内部还是 HandleProxy 入口。

## SelfHeal 升级：看最后一次非视觉 attempt 自动转 success

**用户新反馈**：截图里 SelfHeal 修了一条 volcengine_auto（duration 48429s 异常），但 attempts 里有 deepseek-v4-flash @ WorkBuddy[15007416187] 首次尝试 已成功 3.11s——SelfHeal 太粗暴直接标 stream_interrupted，掩盖了实际有渠道成功的事实。应自动升级为 success 并复用 attempt 的 final_model/channel/tokens/stream/duration/status。

**实现**（`plugins/route-log/service.go`）：
- 新增 `lastNonVisionAttempt(ctx, requestID)` 取最后一次 `action != '视觉识别' AND finished_at IS NOT NULL` 的 attempt（按 step_no DESC LIMIT 1）。视觉是预处理不算主链路成功信号。
- `SelfHeal` 收尾前查该 attempt：若 `result='success'` 则走"升级"分支，用 attempt 数据把 request 标 `success` + 清空 error_message + finished_at 用 attempt 结束时刻 + duration 用请求 started→attempt finished（包含失败重试时间，更诚实）；否则保持原 `stream_interrupted` 收尾。
- 两条 UPDATE 都带 `WHERE result='running' AND finished_at IS NULL` 防并发。

**新增测试**（`plugins/route-log/service_test.go`）：
- `TestSelfHealPromotesSuccessfulAttempt`：3 次 attempt（视觉成功 → 主链路首次失败 502 → 切换渠道成功）→ SelfHeal → 断言 result=success + final_model=glm-5 + final_channel_id=ch-y + http_status=200 + tokens 复用 + stream=true + error_message 清空 + duration ≈ 完整时间。
- `TestSelfHealIgnoresVisionOnlyAttempts`：视觉成功但主链路失败 → 仍走 stream_interrupted（视觉不算）。

**坑**：第一次写 SQL 把 `result = 'success',` 拆成 `'success,` 换行接 `duration_ms`，导致字符串没闭合报语法错误；改成单行 `,` 闭合即可。
