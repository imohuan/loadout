## 模型测试 404 / 中转 401 排查（跨 3 轮）

用户报「模型测试页 models 404 + 使用中转时报 401，但直接测模型能过」。

**结论（三层）：**
1. **models 404 是正常的**：`copilot.tencent.com/v2` 上游没有 `/models` 端点（curl 实测 404），Loadout `fetchChannelModels`（`admin-api/service.go:368`）把 404 当错误持久化到 `channel.models_error`，前端红字常驻。chat 路径一直通，红字不影响使用。
2. **中转 401 根因**：workbuddy 渠道 key 是 codebuddy Keycloak JWT（1266 字符，`iss=www.codebuddy.cn/auth/realms/copilot`），key 本身有效（curl 实测 200）。真正的坑在 `model-gateway/proxy.go:246` `proxyForward`：转发时把客户端所有 header 原样透传（只剔除 hop-by-hop 与 Authorization），**`x-api-key` 不在剔除名单**。copilot.tencent.com 优先读 `x-api-key` 认证 → 客户端带了它 → 401。测试路径 `/api/test/chat`（`test_proxy.go`）只设 Content-Type+Authorization，所以测试能过。
3. **验证方法**：解密 `.secret`（`~/.loadout/data`）拿渠道 key（写临时 Go 程序用 `store.New` + `Decrypt`，注意传 Windows 原生路径否则 store.New 会重建 .secret）；`route_attempts` 表显示 volcengine_auto 聚合首次尝试打 workbuddy 渠道 401 → failover volcengine 200。

**待修复**：`proxy.go` 转发剔除名单加 `x-api-key` / `api-key`（待用户确认后改）。

**已修复（用户确认定向方案）**：
- `model-gateway/proxy.go:246` `proxyForward` header 复制循环：仅当渠道 `base_url` 含 `copilot.tencent.com` 时跳过 `X-Api-Key` / `Api-Key`，其他平台保持原样透传。
- 新增 `isCopilotTencentBaseURL` 判定函数（`proxy.go`，`openAIBaseURL` 旁）。
- 新增测试 `TestHandleProxyStripAltAuthOnCopilot`（普通渠道透传 + 判定函数命中/不命中）。

## volc-free-quota：account_id 断链 + 模型匹配 bug + 强制关停（force_block）

用户反馈：额度监控没生效，模型手动恢复后又产生真实消耗，且持续 429 无法测试。排查发现三个实质问题 + 一个缺失功能。

**修复的 bug：**
1. `ListConfigs` SELECT 漏选 `v.account_id` → `Config.AccountID` 永远空；`ListStatus` 又拿 `cfg.ChannelID` 传给期望 accountID 的 `ListModels/ListUsage` → 前端永远看不到模型额度。修复：SELECT 补 `v.account_id`；ListStatus 按 account_id 查询 + 同账号多 Key 缓存去重。
2. **模型恢复后真实消耗的根因**：`checkAllCandidatesExhausted` 用精确 `WHERE model = ?` 匹配 API 模型名（如 `doubao-1-5-pro-32k-250115`），但库里 `volc_quota_models.model` 存的是归一化 product 名（`doubao-pro-32k`），永远匹配不上 → 拦截不触发。修复：改用 `matchOne` 模糊匹配（与刷新时 `matchQuotaToAPIModels` 同一套逻辑），按账号聚合并判定 allExhausted。
3. `db_test.go` 迁移数期望滞后：v12 加入后 count 10→12、incompatible 测试插 v13。

**新增功能（用户需求）：**
- **强制关停 force_block**：`volc_quota_config` 加 `force_block` 字段（migration v12）。开启后 `HandleProxyBeforeUpstream` 才执行拦截（按 volc_quota_models.status='exhausted' 模糊匹配），否则走 model_states 冷却逻辑。这样用户「全部恢复」后，只要 force_block 开着，请求仍会被额度表拦下，不会产生真实消耗。
- 前端：types.ts 补 account_id/force_block 字段；VolcQuotaCard.vue 表单加「强制关停」Switch + 折叠行加「强制关停」徽章。

**验证**：`go test ./core/db/ ./plugins/volc-free-quota/`、`go build ./...`、`go vet` 全绿；`vue-tsc -b --noEmit` + `vite build` 通过；重编译 `bin/loadout.exe`（27MB，02:16）。
