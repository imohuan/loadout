### 问题

## 每次渠道尝试安检管线（分析 + 计划，未实施）
- 用户报 bug：敏感词/字段过滤等输入侧能力只在请求入口执行一次（ProxyBeforeUpstream 挂在 proxyHandle），渠道切换后不生效。用户确认：规则是模型+渠道共同配置；需求是"每次请求模型都走一轮安检"。
- 根因（代码确认）：
  1. `proxy.go proxyHandle` 的 before 钩子只执行一次；`proxyForward` 同模型多渠道 failover 复用已处理 body 不重算规则；聚合切模型（tryProxyAggregateFailover 递归 proxyForward）完全跳过 before 钩子。
  2. 能力路由用 pipe.Request.Model（被 aggregate 改写为首个目标模型）+ ChannelScopeFromMetadata（首次渠道上下文）匹配 → 切换后规则失配。
  3. 附带：before 钩子执行时渠道未解析（resolveProxyChannels 在 proxyForward 内），非聚合/非 v2 前缀请求 scope 空 → 渠道约束路由首次就不命中。
- 用户提出更优架构：把"完整模型请求（含安检）"抽成函数，内部切换模型/渠道都调用它。
- 设计（计划 docs/plans/2026-08-22-attempt-security-pipeline.md）：
  - 新增事件 `ProxyBeforeAttempt` = "proxy:before-attempt"
  - `proxyForward` 抽出 `proxyAttempt`（单次尝试：注入 __current_channel/__current_channel_base_url → Waterfall(ProxyBeforeAttempt) 安检 → 构造请求 → 发送 → 输出处理；返回 (pipe', handled)，安检拒绝=终止整个请求不换渠道）；body 从循环外移到循环内
  - sensitive-filter / field-filter 改挂 ProxyBeforeAttempt；aggregate / volc-free-quota 留 ProxyBeforeUpstream（入口一次）
  - 聚合 failover 递归 proxyForward 天然覆盖切模型
- 关键实现细节：mockCtx 支持任意事件；渠道按 Models 精确匹配（空=全匹配）；failover mock 需重设 __current_channel 否则 resolveChannels 锁死在旧渠道；__retry_count<10 防递归死循环。
