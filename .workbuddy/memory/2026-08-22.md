## model-gateway 上游错误日志补全 + 重复前缀 bug 修复

### 问题
- 用户截图：UI 显示 `上游返回错误(500): 上游返回错误(500)` —— 双重前缀。
- 用户原话：「我完全看不到你的错误日志详情信息」 —— loadout.log 里只有 HTTP 边沿状态日志，没有任何上游错误体。

### 根因
1. `upstreamErrorMsg`（service.go）自己拼了 `"上游返回错误(N): message"`，外层 `proxyHandle`（proxy.go:367）又 `fmt.Errorf("上游返回错误(%d): %s", ...)` 再套一层。两层冗余 → 上游 body 没有 error.message 时产生「上游返回错误(500): 上游返回错误(500)」。
2. `proxyAttemptLog` 只写 `route_log`（DB），slog 文件日志（loadout.log）记录为零。

### 改动
- `plugins/model-gateway/service.go`
  - `upstreamErrorMsg` 退化为纯 message 抽取（不带前缀）
  - 新增 `upstreamErrorSummary(status, msg)` 统一收口
- `plugins/model-gateway/proxy.go`
  - 三个分支补 s.lg.Error：网络错、上游 HTTP 4xx/5xx、全渠道失败汇总
  - 错误体读上限 4096 → 8192 字节
  - 关键字段：request_id / channel_id / channel_name / channel_group / base_url / upstream URL / status / error_message / response_body / duration_ms
- `plugins/model-gateway/proxy_test.go` 三组回归测试锁定行为

### 验证
- `go build ./...` 通过
- `go test ./plugins/model-gateway/ -count=1` 全过 (6.5s)

## ChannelRef 渠道名称快照：Key 删除后兜底显示「@渠道名(Unknown)」

### 问题
- 模型测试日志（RouteLogTable）显示「@渠道名(key名)」，key 在渠道管理里删除后显示为空。
- 根因：日志只存 final_channel_id（key 的 id），显示时用 id 去 channels 列表查，key 删除后查不到 → formatChannelRef 返回空串。

### 用户规则
- 渠道名称 + key 名称都有 → `@渠道名(key名)`
- 只有渠道名称 → `@渠道名(Unknown)`
- 只有 key 名称或都没有 → 空

### 改动（4 个文件）
1. `frontend/src/lib/types.ts`：RouteLog 加 `final_channel_name?`，RouteAttempt 加 `channel_name?`（快照字段）
2. `frontend/src/composables/useChannelRef.ts`：ChannelRefInput 加 `channel_name?`；formatChannelRef 兜底——segments 空时若有 channel_name 返回「渠道名(Unknown)」，否则空
3. `frontend/src/views/ModelTestView.vue`：生成测试日志 entry/attempt 时从 channels 查渠道名称快照写入；syncTestLog/expand 用后端 detail 覆盖时保留快照（后端字段缺失时 ?? entry 值）
4. `frontend/src/components/route-logs/RouteLogTable.vue`：channelRefFor / finalChannelRef 返回类型加 channel_name，把日志快照传给 ChannelRef

### 关键点
- 测试日志是前端本地生成（localStorage），生成时渠道还在 channels 里，是存快照的唯一时机；后端 detail 无此字段，merge 时必须显式保留。
- 后端 route_requests 表没有渠道名称字段（只有 final_channel_id / final_channel_ids / final_channel_base_url），普通路由日志页 key 删除后仍会显示空——未做后端迁移，用户主要看测试日志。
- 验证：vue-tsc --noEmit 通过。
