## 桌面端托盘功能（Wails v3）
- 新增 `apps/desktop/backend/app/tray.go`：`setupTray(app, win)` 创建系统托盘。
  - 菜单：打开 Loadout（恢复窗口）/ 打开网页（`http://127.0.0.1:3000` 本地 Web 版）/ 退出（`app.Quit()`）。
  - 左键单击托盘图标 → `win.Show().Focus()`。
- `runner.go`：`win.RegisterHook(events.Common.WindowClosing, e.Cancel() + win.Hide())` 拦截关闭 → 点 X 只隐藏到托盘；唯一退出途径是托盘「退出」。
- **Wails v3 关键机制**（踩坑记录）：
  - 关闭拦截必须用 `RegisterHook`（hooks 先于内置 listener 执行），`OnWindowEvent` 是异步 listener，拦不住。
  - `Common.WindowClosing`(1030) == `Windows.WindowClosing`，同一个事件 ID。
  - Windows 托盘：设了 menu 后右键自动弹菜单；`OnClick` 是左键回调。
  - `app.Quit()` 走 `impl.destroy()`，不经过 Closing hook，可干净退出。
  - App 没有公开日志方法（`error` 是私有），用标准库 `log`。
- 验证：`go build -tags production` 通过（dist/app.exe 24.7MB）。

## MCP 进程生命周期管理（enabled 开关 = 进程起停）
- **根因**：`core/mcpkit/mcpkit.go` 的 stdio 分支 spawn 子进程时漏了 `cmdutil.HideWindow(cmd)` → 桌面端每次起 stdio MCP 弹黑框闪关，stdio 管道断裂、工具列表读空。
- **改动**：
  - `mcpkit`：buildTransport 转方法并加 HideWindow；新增 `Connect(ctx)`（强制建连拉起子进程）、`Alive()`（Process != nil && ProcessState == nil 判存活）、`LastError()`（记录最近建连失败原因供 UI 展示）；ensureSession 失败时 Kill 孤儿进程。
  - `mcp-hub`：新增 `SetServerEnabled(ctx,id,enabled)`（开→Connect 常驻，关→Close+移出池）、`StartEnabled(ctx)`（启动时并行拉起所有 enabled）、`ServerStatus(id)`（running/stopped/failed）、`Close()`（实现 io.Closer，`asm.Unload()` 自动调用杀所有子进程）。
  - `admin-api`：list 合并 status/error 返回（`mcpServerWithStatus` 嵌入 MCPServer）；create/update/delete/replace 全部联动进程生命周期；**update 总是先停再拉**（保证编辑配置生效）。
  - `servercore.assemble`：mux 组装后同步调 `hub.StartEnabled(ctx 30s)`，启动自动恢复。
  - 前端：McpPanel 状态列改 运行中(绿tint)/已停止/失败(红+tooltip 错误原因)，兼容旧后端无 status；toggleServer 启动失败 toast.error。
- **设计决策**：崩溃不自动重启（用户选择），UI 显示 failed 状态；DB 的 enabled 保留用户意图（启动失败不回滚）。
- **验证**：根 module + desktop module `go build` 通过；mcp-hub/mcpkit/admin-api 测试全绿；pnpm build（vue-tsc）通过。

## 桌面/网页免二次登录（SSO）
- **问题根源**：WebView2 和 Chrome 的 cookie 存储物理隔离，`loadout_session` 是 HttpOnly + host-only cookie，两边各登各的；Wails v3 无 cookie 读取 API，桌面 Go 侧拿不到 WebView2 里的会话。
- **方案（已实现）**：桌面签短效 JWT → URL 带 `?sso=` → 网页版换正式 cookie。
  - 后端 `plugins/admin-api/service.go` 加 `POST /api/sso/login`：ParseToken 校验短效 token → 用 claims.Username 重签完整 TTL 会话 Set-Cookie；仅限本机回环来源（isLoopback）。
  - 前端 `stores/auth.ts` 加 `ssoLogin(token)`；`router/index.ts` beforeEach 检测 `?sso=` → 自动登录 → `history.replaceState` 清参数。
  - 桌面 `tray.go` 的 `ssoWebURL()`：`store.New(lconfig.DataDir)` 读 secret + users.json 第一个用户名 → `auth.SignToken(secret, username, 30s)` → `http://127.0.0.1:3000/?sso=<token>`。读不到用户回退 "admin"。
- **坑**：`loadout/core/config` 与 `proxyui/backend`（package config）同名 → 前者别名 `lconfig`。
- 安全：token 30s 短效 + sso/login 限 127.0.0.1；admin-auth middleware 只验签名/过期、不查用户存在性，所以重签 token 用 claims.Username 即可。
