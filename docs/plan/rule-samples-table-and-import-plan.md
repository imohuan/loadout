# 失败规则页：样本回放表格接入 AxTable + 导入上限修复

> 用户反馈两点：(1) 样本回放表格没用项目自建的 AxTable（另两个表用了）；
> (2) 「结果」列宽度不够；(3) 导入历史失败似乎被限了数量。

## 现状（Chrome MCP 实测 + 代码核对，证据在手）

### 问题 1：样本回放表格没接入 AxTable

Chrome 实测（page 4，`document.querySelectorAll('table')`）：
```
[{ i:0, wrappedByAxTable:false, heads:['来源','状态码','业务码','模型','错误摘要','匹配规则','结果','操作'] }]
```
同一页面的另外两个表格在源码里是 `<AxTable>...<Table>`（RulesView.vue:820、946），
样本表格只有裸 `<Table>`（RulesView.vue:1059）。
后果：该表没有 AxTable 的能力 —— 列宽跟随内容、表头边界可拖拽调宽、双击恢复自动宽度、
max-w-* 真正生效（超长内容换行而不是被切）。

### 问题 2：「结果」列宽度不够

Chrome 实测单元格宽度：
```
结果列  '已匹配 · 禁用模型'  宽 121px   （内容会被压）
操作列  ''                  宽 190px   （空着却最宽）
```
源码给的 `w-[150px]` 是偏窄的「固定值」，而内容形如「未命中规则 no_rule_matched」
（约 20 字符 + 徽标内边距）。且未接 AxTable 时列宽不可拖，用户也无法自救。

### 问题 3：导入历史失败的数量

两层限制，都要处理：
1. 上限：`ImportFromDecisions` 默认 2000、硬顶 5000（samples.go:165）。
   实测库里 `rule_decisions` 611 行，暂未触顶；但用户机器上跑久了会触顶，
   而 UI 上完全不提示「只导了最新 N 条」，用户会以为全导进来了。
2. 去重：指纹 = 「状态码 + 业务码 + 归一化错误文案」，同类错误只留 1 条。
   实测 605 条有错误的历史 → 去重后 8 条（457 条 403 合并成 1 条）。
   这是**设计意图**（回撤要的是「故障类型」清单，不是 457 行噪音），
   但用户不知道，需要把「合并了多少条」显式告诉用户。

## 改动

### M1 样本表格接入 AxTable
- [ ] M1.1 `<Table>` 换成 `<AxTable><Table>`，与其他两个表写法一致
- [ ] M1.2 列宽改为「内容优先 + 上限」：错误摘要 `max-w-[360px]`、
      结果 `min-w-[160px]`（不再写死 150px）、匹配规则 `min-w-[160px]`、
      操作列收窄（内容只有图标按钮）

### M2 导入可观测
- [ ] M2.1 后端 ImportFromDecisions 返回值补 `scanned`（扫描了多少条判定日志）
      与 `limit`（本次上限），让 UI 能说明「扫了 N 条、合并成 M 条」
- [ ] M2.2 前端 toast 明确说明：扫描 N 条 → 新增 X 条样本（同类已合并），
      并在触及上限时提示「仅扫描最新 N 条」
- [ ] M2.3 （可选）提供「导入全部」：limit=0 时用 maxImportLimit，并在响应里回带

### M3 验证
- [ ] M3.1 go build + 相关包测试
- [ ] M3.2 Chrome MCP 实测：样本表格 wrappedByAxTable=true、结果列宽度足够、
      导入 toast 文案正确
